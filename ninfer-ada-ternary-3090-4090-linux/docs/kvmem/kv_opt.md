高效保证大模型内存使用与节省 GPU 显存，核心策略是构建一个 **“分级存储 + 动态调度”** 的体系，让不同热度的数据在 GPU 显存、系统内存和硬盘之间按需流动。关键路径是 **模型权重压缩**、**KV 缓存分层管理**和**架构级优化**。

### 🗂️ 模型权重：从“全量驻留”到“压缩与分片”

模型权重是显存的基础占用。纯 FP32 精度的 7B 模型权重约 28GB，远超消费级显卡容量。最直接的手段是**量化**，将精度降至 INT8、INT4 甚至更低。实测中，MixT 张量混合压缩框架在 LLaMA2-7B 上实现了推理显存降低 **60.4%**，同时模型综合能力几乎不变。若单卡显存依然不足，可启用**张量并行**，将模型拆分到多张 GPU 上。

### 📦 KV 缓存：显存消耗的“大头”与分级存储

KV 缓存随上下文长度线性增长，是长文本推理的显存杀手。为它建立一套 **“GPU 显存 → CPU 内存 → SSD”** 的三级存储调度，是最有效的节省手段。

*   **GPU 显存层**：基础层。利用 **PagedAttention** 技术，将 KV 缓存分割成固定大小的“页”，按需分配，可将显存碎片率从超过 60% 降至 5% 以下，支持更大的并发批量。
*   **CPU 内存层（CPU Offload）**：将暂时不用的 KV 缓存块卸载到 CPU 内存。一项研究表明，通过将 KV 缓存卸载至 CPU RAM，在 GTX 960（4GB 显存）上实现了高达 **60%** 的峰值显存降低，使上下文长度扩展到 3500+ token，而生成速度仅损失约 12-23%。vLLM 提供了 `--swap-space` 参数来控制该层的空间大小。
*   **SSD/硬盘层**：作为容量最大、速度最慢的层级，用于持久化存储极长的上下文或跨请求复用的缓存。NVIDIA Dynamo 的 KV 块管理器（KVBM）就支持将 KV 缓存卸载到本地或分布式 SSD，并利用 NIXL 实现高效传输。MoonCake、LMCache 等项目也采用类似思路，将 KVCache 与计算解耦，通过分布式存储池降低显存压力。

### ⚙️ 架构级优化：从源头减少缓存体积

除了“搬运”数据，从模型架构层面减少 KV 缓存本身的大小是更根本的方案。

*   **跨层共享与压缩注意力**：DeepSeek V4.1-Flash 的 **CSA2 架构**实现了跨层 KV 复用和跨层 Top-K 索引复用，让 40 层网络共用同一份副本，宣称将 KV 缓存体积压缩了 **437 倍**，大幅降低了运行时显存占用。
*   **动态精度分配**：KVC-Q 框架提出了“动态信息保真度”范式，根据 token 的重要性动态分配量化位数（而非粗暴地全部保留或丢弃），在约 **70%** 的 KV 缓存压缩比下，仍能保留超过 94% 的基线性能。

### 💡 实操层面的显存节省技巧

在部署时，可以通过调整推理引擎参数来进一步压榨显存空间：

*   **限制上下文与并发**：降低 `--max-model-len`（最大序列长度）和 `max_num_seqs`（最大并发数）可以直接减少 KV 缓存的预留空间。
*   **启用 FP8 KV 缓存**：在 vLLM 中设置 `--kv-cache-dtype fp8`，可将 KV 缓存的内存占用减半。
*   **调整 GPU 内存利用率**：通过 `--gpu-memory-utilization` 控制 vLLM 可用的显存比例。在显存紧张时，适当降低该值（如 0.8）虽会牺牲部分吞吐，但能避免 OOM 崩溃。

总结来说，高效的显存管理不是单一技术，而是一个**组合策略**：先用**量化**压缩静态权重，再用**分页与卸载**管理动态缓存，最后通过**架构优化**从源头减负。
