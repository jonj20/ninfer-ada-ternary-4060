## 1. 解码（decode，T=1）

| 阶段 | tok/s | 相对 reference | 关键手段 |
|---|---|---|---|
| reference | 3.36 | ×1.0 | — |
| 一期 | 8.33 | ×2.5 | SIMD 四列 quad 解码，warp-per-row |
| 二期 | 15.3 | ×4.6 | int8 激活 + `__dp4a` 整数点积 |
| 二期 b | 17.6 | ×5.2 | tail 向量化（每 lane 领整组） |
| **三期（当前默认）** | **22.6** | **×6.7** | 三进制原地递推，重排 lane→列映射 |

- **llama.cpp 同机同文件 22–28 t/s → 已收平到其下沿**（优化前差距 ×7.4）
- 服务端实测中位 **22.57 tok/s**（5 次采样 22.54–22.64）
- 微基准（真实形状，权重带宽）：gate_up 89.6→**129.4**、MLP down 133.2→**168.1**、
  attn/GDN 129.3→**152.4** GB/s；312 MB 冷载荷 96.7→**137.5 GB/s**
- 40 寄存器、**无溢出**；与原 dp4a 内核在 K=5120/1536/17408 上**逐位一致**

**当前位置**：136 GB/s / 249.6 GB/s = **54% 带宽**；算力 1.24 TFLOP/s / ~105 TFLOPS = **1.2%**。
算术强度 9.1 FLOP/byte，比拐点（420）低 46 倍 → **硬性访存受限**，"GPU 占用率"低是正常读数。

## 2. 预填充（prefill）

| | 之前 | 现在 | 提升 |
|---|---|---|---|
| 吞吐 | 10.9 tok/s（**与长度无关**，恒定） | **111 / 122 / 125 tok/s**（401/781/1541 tok） | **×11.5** |
| 1541 token prompt | 142.5 s | **13.4 s** | ×10.6 |
| SSE 首 token | 2.10 s | **0.40 s** | ×5.3 |
| 8192 上下文填满 | 约 12.6 分钟 | 约 65 秒 | ×11.6 |

**根因**：参考分块 GEMM 每 CTA 只做 1 个输出行 → 激活被重复读 rows 次（gate_up 每层约 108 GB
L2 流量），302 token × 27B 参数 = 1.63e13 FLOP 花了 28.1 s，即 **0.58 TFLOPS = FFMA 峰值的 0.4%**。

**形状实测（对参考 t8 内核）**：gate_up **×11.7**、MLP down **×12.1**、attn/GDN **×11.0**、
LM head **×11.4**（T=302）；T=9（serve 的实际调用粒度）**×8.2–12.0**。
绝对值统一在 **3.1–3.4 TMAC/s**（dp4a SIMT 峰值的 ~21%）。

## 5. 已证伪（勿重试）

单平面重打包（与三平面持平或更慢）· cp.async / shared staging（decode 权重，70 vs 110 GB/s）·
每 warp 2 行 · 4 路累加器 · `__ldcs` · kernel 内重复量化 · 激活预载 shared（decode）· scale 预载
shared · **MTP 投机**（23.64→11.52 tok/s，慢一倍）· **并发批处理**（聚合 22.04→3.18 tok/s）

## 7. 已知问题

1. **间歇性 illegal address**（先前就存在，与本轮优化无关）：`gqa_attention_prefill.cu` /
   `l2norm.cu` 偶发 `cudaErrorIllegalAddress`，13 次里 2 次，随后 11 次未复现，出现在 T=9 预填充
   路径上。再遇到建议用 `compute-sanitizer` 抓一次。
2. **`/mnt/d` 9p 挂载不稳定**：`ls` 能列出文件但 `grep`/`stat` 打不开；曾有一次 edit 失败把
   `ternary_rowsplit_gemm.cu` 截断成 0 字节（已从 git 重放恢复），`tools/verify/ternary_gemv/`
   下的文件也被环境删过一次。**改动前先确认文件大小，重要改动后立刻提交。**
3. **测量噪声**：SM 频率随电源在 1.68–2.01 GHz 摆动，单次计时 **±20%**，带宽结论须取多次 median
   （`gemv_bandwidth.cu` 已内置 5 次）。
4. `ruff` / `mypy` 有 225 处既存报错，均在未触碰的 Python 侧。

## 8. 复现命令

```bash
# 正确性门禁（改完内核先跑）
NVCC=/usr/local/cuda-13.1/bin/nvcc tools/verify/ternary_gemv/run_checks.sh reference

# 起服务（默认 ctx 48000 / 输出不设限 / 非思考模式）
scripts/run-ternary-4060.sh
NINFER_CTX=32768 scripts/run-ternary-4060.sh      # 长对话更稳
NINFER_MODE=think scripts/run-ternary-4060.sh     # 思考模式 + 对应采样参数

# 端到端 A/B 开关
NINFER_TERNARY_PTQ1_RECURRENCE=0   # 退回每 lane 一个 trit 的解码内核（17.0 tok/s）
NINFER_TERNARY_PTQ1_PREFILL=0     # 退回参考分块 GEMM（prefill 10.9 tok/s）
NINFER_TERNARY_PTQ1_PREFILL_VERBOSE=1   # 报告 prefill 快路径为何没走上
NINFER_TERNARY_PTQ1_DP4A=0        # 退回 bf16 激活点积（13.2 tok/s）
NINFER_TERNARY_PTQ1_GEMV=0        # 退回 reference 解码（3.36 tok/s）
```
